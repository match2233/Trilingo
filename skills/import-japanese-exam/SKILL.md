# 日语试卷导入与题库维护（Trilingo）

这份文档不是流水线手册，而是**踩过坑之后的经验总结**。前半是"怎么做"，
后半是"别怎么做"——后者更值钱。

## 一、题库的数据结构（先理解这个）

一个试卷集 = 一个 JSON：

```json
{
  "version": 2,
  "meta": {"id": "jlpt-n5", "name": "JLPT-N5", "kind": "jlpt",
           "desc": "…", "duration_min": 105, "order": 20},
  "lessons": [{
    "lesson": 3, "title": "2010年07月", "duration_min": 105,
    "audio": "exams/jlpt-n5/audio/2010.mp3",
    "sections": [{
      "no": 1, "title": "文字・語彙（31 题）", "kind": "choice",
      "group": "文字・語彙",
      "items": [{
        "id": "Q03-S1-1",
        "prompt": "先週、デパートに…",
        "prompt_rich": "__先週__、デパートに…",
        "prompt_image": "exams/x/prompts/p03-q001.png",
        "image": "exams/x/fig/p03-f01.png",
        "options": ["…","…","…","…"],
        "answer": 2
      }]
    }]
  }]
}
```

关键约定：

* `id` 必须**稳定**（`Q<卷号>-S<大题号>-<小题号>`），收藏和进度都挂在它上面。
* `group` 决定「题目选择」面板的分类（文字・語彙 / 文法・読解 / 聴解）。
* `answer: null` = 原卷没答案，界面走"自评"（听完自己判对错）。
* 图片路径相对 `data/`，文件缺失时界面静默跳过，不会崩。

## 二、导入流水线（能用的那条）

```bash
# 1) OCR: PDF -> 逐页行文本(带坐标/置信度)
python tools/ocr_paper.py <pdf> --pages 1-12 --out data/ocr/lay_x.json

# 2) 组装: 行 -> 四选一题目 (正则搞不定的版式交给模型)
python tools/assemble_questions.py <ocr.json> --out q.json [--mode reading]

# 3) 建卷: 拼成三个分区 (文字/文法読解/聴解), 答案按题号对齐
python tools/build_paper_full.py --paper 3 --title 2010年07月 \
    --pdf "<真题.pdf>" --answers data/ocr/answers_2010.json \
    --text-pages 3-4 --reading-pages 5-8 --listening-pages 9-11

# 4) 富文本: 从像素里读下划线/标红
python tools/rich_markup.py --paper 3 --title 2010年07月 --ocr <ocr.json> --pdf <pdf>

# 5) 插图: 非听力题的图 (整页墨迹 - 文字行覆盖区)
python tools/attach_figures.py --paper 3 --title 2010年07月 --ocr <ocr.json> --pdf <pdf>
```

12 页一套的版式通常固定：1-2 封面说明，3-4 文字・語彙，5-8 文法・読解，
9-11 聴解，12 参考答案。但 **2025 年的卷子把文法読解放前面、文字語彙放后面**，
所以每套都要先看一眼首页文字再定页范围。

## 三、经验教训（按主题）

### 1. OCR

* rapidocr 自带的**中文模型认不出假名**（「話させて」只认出「話」）。必须换成
  日语 rec 模型：`tools/fetch_ocr_models.py` 会下载 `japan_rec_crnn.onnx` +
  `japan_dict.txt` 并生成配置（`rec_img_shape` 32 高、加 `rec_keys_path`）。
* 换完之后「先週、デパートにかいものにいきました。」能一字不差读出来。
* 速度 3-5 秒/页；假名偶有混淆（さ/き、ぽ/ぼ、っ/。），需要 AI 顺一遍。
* **提高渲染倍率救不了没有文字层的扫描件**：2024-12 那套从 2.2 提到 3.4 倍，
  行数完全没变（那几页本身只有标题 + 水印）。

### 2. 乱码与扫描件

* 「有文字层」不等于「能用」：有的 PDF 文字层是**逐字替换乱码**
  （`伈京寸` = います、`言舌` = 話），而且是**变长替换**（の→"(J)"、で→"T!"），
  不是一对一，反推码表得不偿失。判据：假名占比低于 25% 基本就是坏的。
* 真扫描件唯一的路是 OCR；OCR 之后让模型"看懂版式"重排。

### 3. 答案表与对齐（最容易出错的地方）

* **答案表就在试卷最后一页**（「参考答案」表格），分三段：文字・語彙 / 文法・読解 / 聴解。
  整页 OCR 会把相邻格子粘在一起（把 3 认成 る），**逐格切、逐格识别**才行。
* **按「卷面题号」对齐，不要按「第几题」**。模型组装返回的 `no` 就是卷面题号
  （2010 文字語彙返回 1..33 但缺 20），少解出几题也能精确套上；
  按位置套会整体错位——实测把「水をください」的答案给成了「みす」。
* 数量对不上时**不要硬套**，改用 AI 答案并标注来源。
* **模型会重排选项**，一重排答案就全错。提示词必须写死：
  「选项按卷面顺序原样输出，不要重排/排序/改写」。
* 官方答案表也可能和题目对不上（抽查 2016 卷「先週」那题就对不上），
  所以"官方"不等于"免检"。

### 4. 减少漏题

* 同一页跑**两遍取并集**：模型每次漏的题不一样。实测 2010 文字 29→31、
  文法読解 29→31；2013 整卷 91→95。

### 5. 图片

* 这些试卷的插图多是**矢量绘制**，PDF 里没有位图对象（pdfium 列出来全是文本），
  只能**按版面裁**，不能"抽取图片"。
* 听力按「番」裁：每页按横向空白切成行带，块多则合并、块少**不硬拆**
  （拆出来是 90px 残图），宁可相邻题共用一块。
* **底边要多留 18px**：四个选项常排两行，一刀切会把第二行切掉。
* 裁完去白边，图才能放大显示。
* 非听力题的图：用「整页墨迹 − 文字行覆盖区」找，取**紧邻**（150px 内）的那块。
  放宽到 700px 会把「苹果盒」挂到完全不相关的题上——**错误的图比没有图更糟**。
* 别用关键词猜有没有图（絵/図/写真/ず/え 会把「えき」「きょうなら」全命中）。

### 6. 富文本（下划线 / 标红）

* 不要用截图糊弄：像素分析能把格式"读"出来，写成文字还能复制、字号统一。
* 标红：`R>130 且 R−G>50`。下划线：文字下方"细而长"的横向深色段，
  **不能要求整行都黑**——下划线只覆盖被考的两三个字（一开始要求 35% 宽度，
  一道都检测不到）。
* 像素区间 → 字符区间用「起点 + 长度/字宽」，两端各自四舍五入会时多时少。
* **OCR 行首常带题号**（`1、`/`ö、`），要减去这个偏移，否则下划线往前串两个字符。

### 7. 界面（真的会踩）

* `FlatButton(width=44)` 是 **44 个字符宽**，放进 grid 会把列撑爆，
  后面的按钮被挤出可视区——看起来像"按钮消失"。要用固定 42×42 的 Frame。
* `_reset_foot()` 会把底栏除提示外的控件全 `pack_forget`，
  新加的常驻按钮刚建好就被清掉（表现为"按钮不存在"）。清完要摆回来。
* 底栏要 `side="bottom" + before=body` 先占位，否则长题干把它顶出屏幕。
* 题干超过 140 字要放进带滚动条的 Text，否则読解文章把选项挤没。
* 题目图限高 300px（听力四个选项要一屏可见），题干截图可以到 430。
* 列表标题：真题卷要显示「2016年 / 2012年12月」，不要显示「第 N 课」。

### 8. 数据层

* `load_bank` 是 `lru_cache` 的，**切换试卷集时必须 `cache_clear()`**，
  否则进 N5 看到的还是新标日的 24 课。
* 按试卷集隔离进度/成绩/收藏要加 `collection` 列并改主键；
  SQLite 改不了主键，只能建新表 + 搬数据（现有数据归到 `shinbunpo-1`）。
* 重建一套卷子会**覆盖整个 lesson**，`audio`/`prompt_rich`/`image` 都会丢，
  要么重建后重跑补齐脚本，要么在建卷器里保留旧字段。

### 9. 工程纪律（血泪）

* **补丁脚本别碰 argparse 段**：`--groups` 被反复追加了三次，
  每次都是 `argparse.ArgumentError: conflicting option string`，整批任务全崩。
  改函数体就够了。
* 用 `Set-Content` 写 JSON 会带 **BOM**，`json.load` 直接 `Unexpected UTF-8 BOM`。
  统一 `encoding="utf-8-sig"` 读、`[Text.UTF8Encoding]::new($false)` 写。
* 建卷脚本最后的 `print` 在 GBK 控制台会抛 `UnicodeEncodeError`（`・` 编不出来）。
  数据其实已经写完了，但日志看着像失败——统一 `PYTHONIOENCODING=utf-8`。
* git push 偶尔 TLS 失败（`schannel: failed to receive handshake`），重试几次通常就好；
  不要因为一次失败就去改 remote 配置。
* `.gitignore` 用正则改容易把敏感文件（`data/sync.json`、`data/llm.json`）放出来，
  改完要 `git check-ignore` 逐个验证。

## 四、已放弃：JLPT-N5 全量导入

2026-10 试过把 11 套 N5 真题全部导入，最后**放弃并删除**。结论供以后参考：

| 卷子 | 结果 |
|---|---|
| 2010/2012/2013/2016/2018（12 页标准版） | 可用，每套 82-95 题，答案来自官方答案表 |
| 2017（拆成 N5V/G/R/L 四份 PDF） | 可用，98 题，靠 `--groups` 分区重建拼起来 |
| 2024-07 / 2025-07 / 2025-12（30+ 页） | 勉强可用，53-69 题，答案靠 AI |
| 2024-12（图片版，水印压在选项上） | **不可用**，最多 24 题 |

放弃的真实原因不是技术，而是**投入产出比**：

1. 每套要人工读一遍答案表（10 套 = 10 张表格），AI 组装的题数总差几道，
   补两遍就要多花一倍 token；
2. 聴解没有答案表时只能自评，体验打折；
3. 同样的精力去做「新标日初级下」这种**版式统一、有官方答案**的教辅，收益高得多。

**教训：先花 10 分钟判断源文件质量（文字层/水印/版式一致性），再决定要不要开工。**
`tools/scan_layout.py` 和 `app/exam_import.py` 的体检就是干这个的——
这次明知源文件差还硬做，才落得删库收场。

## 五、速查：出现这些现象先查哪里

| 现象 | 先查 |
|---|---|
| 题号按钮"消失" | 是不是用了 `FlatButton(width=…)` 撑爆 grid |
| 底栏按钮不见 | `_reset_foot()` 是否把它清了 |
| 选项被挤出屏幕 | 题干是否 >140 字没进滚动框；图是否超过 300px |
| 切了卷子还是旧内容 | `minna.use()` 里有没有 `cache_clear()` |
| 答案整体错位 | 是否按"第几题"而不是"题号"对齐；模型有没有重排选项 |
| 下标划线位置串了 | OCR 行首题号偏移有没有减掉 |
| 图挂错题 | 邻接阈值是不是放太宽（应 ≤150px） |
| 音频放不出 | Windows MCI 在这台机器上打不开 mp3，用 pygame.mixer |
